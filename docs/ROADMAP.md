## 二、相对 temuagent 的改进（面试可讲）

1. **领域换成自己有一手数据的场景**：数据源是自有账号创作者后台导出，不再有"模拟数据冒充真实业务"的软肋。
2. **事实/决策分离**：事实表只增不改 + 评分版本化快照，任何一次评分都可追溯到当时的输入数据批次（`imported_batch` 字段）。
3. **双引擎**：内容分 × 商品分合成，带货账号"选内容"和"选品"两个决策显式拆开，各自可解释。
4. **合规升级**：从单一风险清单升级为 P0/P1/P2 三级 + 商品类目资质检查（缺证食品/保健食品直接拦截，端到端已验证）。
5. **导入健壮性**：整批校验拒绝（无半批导入）、同批重复与跨批跳过分开计数、BOM 兼容、审计自动留痕。

**踩坑记录（面试可讲）**：评论分类的词表冲突——"求同款链接"里"链接"vs"求同款"跨意图命中、"会不会起球"（咨询）vs"起球了"（投诉）语境差异，解法是按意图优先级重排词表 + 把"起球了/掉色了"等带结果态的表述与裸词区分。这是规则引擎的经典精度问题，也是为什么保留 LLM 辅助通道。

## 四、明确不做的事（面试被问"为什么不做"时的答案）

- **不做自动发布**：发布动作由人执行，系统止步于审批——平台风控风险 + 与项目"人在环上"哲学一致。
- **不做爬虫采集**：数据全部来自创作者后台官方导出，零风控风险零维护成本。
- **不为了 multi-agent 而 multi-agent**：当前单链路 + 确定性工具已覆盖需求，多 Agent 协作是手段不是目的（dxl 的 README 同样观点）。
- **评分不调大模型**：评分是业务规则计算，必须可复算可审计；大模型只出现在第 2 周的 RAG 和评论意图分类里，且输出仅作草稿。
